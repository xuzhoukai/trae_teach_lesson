# Mission: 把 Redis 正确落地到工作中的系统

## Why
你有 3 年以上后端经验（Go + Java），独立负责过模块和服务的实现，但 Redis 目前只会 SET/GET。目标是：在自己负责的服务里**放心地引入 Redis**——选得对（该不该用、用哪种数据结构）、不出线上事故（不把内存撑爆、不踩一致性坑）、出了事能排查。不是背八股应付面试，而是能对同事解释清「为什么这么写」和「什么情况下不能这么写」。

## Success looks like
- 能在一个具体业务里判断「**该不该**上 Redis」，并说清收益与付出的代价
- 能从业务的读写模式出发**选对数据结构**，而不是一律用 String 存 JSON
- 能给出不会泄漏内存的键方案：**键命名 + 过期 + 淘汰策略**三者配套
- 能写出一个正确的缓存读取路径，并说清穿透 / 击穿 / 雪崩的应对与一致性边界
- 能用 Redis 实现分布式锁、限流这类原语，并且知道**它在什么情况下并不安全**

## Constraints
- 每节课 = 一个紧凑概念 + 一个动手练习（真的敲 `redis-cli`），配即时反馈
- 本地有 Docker，可以跑真实 Redis；练习以官方镜像 `redis:7.4` 为准（`HEXPIRE` 等字段级过期从 7.4.0 才有）
- 主力技术栈 Go + Java，代码片段两者都要给
- 素材为**仿真需求**（电商 / 优惠券 / 订单类），没有可公开的真实项目

## Out of scope（本阶段明确不做）
- **高可用与扩展**：主从复制原理、哨兵选主、Cluster 分片与槽位迁移
- **源码级实现**：SDS、跳表、事件循环、单线程模型的实现细节
- Redis 之外的缓存体系（CDN、进程内缓存框架选型）——需要时仅作对照提及
