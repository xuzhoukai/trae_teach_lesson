过期与内存淘汰速查卡

key 消失只有两种原因：你让它过期，或 Redis 把它淘汰。这张卡把两者的命令、判据和排查路径压在一页里。所有结论出自官方文档，链接见Resources。

1先分清两条生命周期

过期 expiration淘汰 eviction
谁决定你（写代码时设的 TTL）Redis（内存超限时自动执行）
触发条件TTL 倒计时归零used_memory 超过 maxmemory
有无 TTL 均可必然有 TTL（否则叫「永久键」）allkeys-* 可淘汰永久键；volatile-* 只淘汰易失键
观察指标INFO stats → expired_keysINFO stats → evicted_keys
能不能关掉能：不设 TTL 即可（但别这么干）能：maxmemory 0 或 noeviction
易错点

把 maxmemory 设成非 0、策略设成 noeviction，结果是：内存满了以后写命令直接报错（读命令仍正常）。很多「线上突然写不进去」的事故是这个组合，而不是缓存逻辑写错了。官方

2TTL 命令全表

目的命令要点
写值并同时设 TTL SET k v EX 300
SET k v PX 300000
SET k v EXAT 1735689600		 一次搞定，优先用这个。EX/PX 是相对秒/毫秒，EXAT/PXAT 是绝对时间戳（做「到零点统一失效」时用绝对时间更准）。
给已有 key 设 TTL EXPIRE k 300
PEXPIRE / EXPIREAT / PEXPIREAT		 可选 NX（仅当原本没有 TTL 才设）、XX（仅当原本有 TTL 才设）、GT / LT（与现有 TTL 比较后再设）。非正超时会直接删除 key，且事件是 del 而不是 expired。
查看剩余寿命 TTL k / PTTL k 返回值语义：正数 = 剩余秒数；-1 = key 存在但没有 TTL；-2 = key 不存在。
查看到期时间点 EXPIRETIME k 返回绝对 Unix 时间戳，便于和监控/日志对齐。
取消过期 PERSIST k 把易失键变回永久键。看到 TTL 返回 -1 时，配合 PERSIST 能确认是自己漏设还是被命令清掉了。
Hash 字段级 TTL
（仅 7.4+）		 HEXPIRE h 300 FIELDS 2 f1 f2
HTTL h FIELDS 1 f1
HPERSIST h FIELDS 1 f1		 只让部分字段过期，适合「一个 Hash 里混了长短命数据」的场景。Redis 7.4.0 起才有，旧实例会报未知命令。

3会清 TTL？——这是本课最该背下来的一节

官方原文："The timeout will only be cleared by commands that delete or overwrite the contents of the key, including DEL, SET, GETSET and all the *STORE commands. This means that all the operations that conceptually alter the value stored at the key without replacing it with a new one will leave the timeout untouched."官方

会清掉 TTL · 覆盖或删除内容

DEL、SET（不带 KEEPTTL）、GETSET，以及所有 *STORE 命令（如 SORT ... STORE）

判据：官方原文只点了这几类——整体替换或删除 key 内容。你自己判断一条命令属于哪一类时，问一句：它是「整体换掉这块值」还是「在原来的值上改」？

后果：缓存键从此变成永久键，内存只增不减——典型的「TTL 被自己写没了」。

不会清 TTL · 原地改值

INCR / DECR / INCRBY、LPUSH / RPUSH、HSET / HINCRBY / HDEL、SADD、ZADD、APPEND、SETBIT

后果：TTL 继续按原节奏倒计时。如果你希望「每次访问都续期」，必须显式再调 EXPIRE，它不会自动续。

最快记住的方式

整体换掉这个 key  → TTL 没了（SET / GETSET / DEL）
在原来那块值上改 → TTL 还在（HSET / INCR / LPUSH / ZADD）

想保留原 TTL 又要整体覆盖：SET k v KEEPTTL
想让它续期           ：HSET 之后补一句 EXPIRE k 300

4SET 的写入选项速查

选项作用适用场景
NX仅当 key 不存在才写分布式锁、幂等地占坑
XX仅当 key 已存在才写只更新不新建，避免制造脏 key
EX / PX设相对过期（秒 / 毫秒）常规缓存
EXAT / PXAT设绝对过期时间戳「全站统一在零点失效」
KEEPTTL保留 key 原有 TTL整体刷新值但不想重置生命周期
GET写入同时返回旧值需要「换了什么」的场景（注意旧值类型必须兼容）

5淘汰策略全表

策略候选范围挑选规则
noeviction不淘汰内存满时写命令报错，读命令仍可用。默认值。
allkeys-lru所有键最久没被访问。官方称「没有理由偏好其它时，这是好的默认选项」。
allkeys-lrm所有键最久没被修改。适合读多写少：保住常读的老数据，清掉陈旧写入。
allkeys-lfu所有键访问次数最少。
allkeys-random所有键随机，适合访问频率大致均匀（如循环扫描）。
volatile-lru / volatile-lrm / volatile-lfu / volatile-random仅易失键同上规则，但只在带 TTL 的键里挑。适合「一个实例同时放缓存和持久数据」——不过官方建议这种情况拆成两个实例更好。
volatile-ttl仅易失键优先淘汰剩余 TTL 最短的。适合你能主动给「不重要的数据」设短 TTL。
两个容易被忽略的细节

1）volatile-* 系列在一个带 TTL 的 key 都没有时，行为退化成 noeviction，也就是开始拒绝写。

2）给 key 设 expire 本身要占内存，所以 allkeys-lru 比 volatile-lru 更省内存。官方

6线上排查：三条命令定位「key 为什么没了」

你要回答的问题看哪里
缓存到底有没有起作用？keyspace_hits / (keyspace_hits + keyspace_misses)，与你的预期命中率对比
key 是被淘汰还是被过期？evicted_keys 高 → 是淘汰，该加内存或调策略；expired_keys 高而 evicted_keys 低 → 是 TTL 设太短了
这个 key 还会不会走？TTL k：-1 = 永久键（多半是 bug）、-2 = 已不在、正数 = 还剩多少秒
事故模板 A · 内存只增不减

现象：实例内存逐日上涨、偶发 OOM command not allowed。
成因：SET 不带 EX，或后续 SET 覆盖时把 TTL 清掉了，键全成了永久键。
定位：抽几个键看 TTL 是否返回 -1。

事故模板 B · 缓存突然大面积不命中

现象：命中率断崖下跌，数据库压力飙升。
成因：大量键在同一时刻集中过期（统一按「零点」或同一个 TTL 写入）。
定位：expired_keys 尖峰 + 写入时间集中。应对方向：让 TTL 离散。
