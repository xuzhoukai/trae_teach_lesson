# 能按失败模式拆重试，但「幂等是重试的许可证」未内化；把「明确失败」说成「无货」

第 4 课练习（2026-10-27）显示：失败模式的枚举已经能独立完成，超时预算在提示后能算对，并且自己提出了「支付第二次尝试改为查单」——这是本课最亮的一笔。但两个关键判断仍在用错误的规则。

## 已掌握

- **失败模式分类完整**：能列出「连不上 / 连上了不回应 / 回应了是错的 / 回应了但很慢 / 部分成功」五类，并主动加了一列「下游执行了吗」——方法论方向是对的。
- **超时预算能算**：首次漏算退避等待（150×3 = 900ms，实际加退避 1200ms > S5）；提示后改为 2 次尝试 + 50ms 退避，得 700ms，正确且留有 300ms 余量。
- **能按依赖区分策略**：主动提出支付超时不重复扣款、第 2 次尝试改为查单——这是「不幂等就重试会做两次」的正确落地，超出预期。

## 缺口（下一课要接住）

1. **判据仍错**：把「执行了 → 不能重试」当成规则，而不是「结果未知 → 有幂等才可重试」。具体三格：「连上了不回应」写成「执行了」，「部分成功」同样写成「执行了」，两者本质是同一类（结果未知），被他拆成两行并都判成不可重试。
2. **「执行了吗」这一列另有两处事实错误**：把「参数/业务校验失败」写成「执行了」（实际是入口即拒、未执行）；把「很慢」也写成「执行了」。
3. **失败不诚实（新缺口）**：库存不可用时选择「直接返回无货」。但库存服务挂了，系统并不知道有没有货——「无货」是用编造的业务事实冒充「明确失败」。与 learning-record 0001 记录的「填不出刺激源就硬填用户」是同一个模式：**未知时不肯写未知，改写成确定结论**。
4. **ADR 3 未独立撰写**：本次给出了样例，用户尚未自己写一版，三节串位是否已修好**无法判定**，不要在下一课当成已解决。

## 亮点（正向证据）

第 4 题的第一问答得好：指出快照过期由**商家承担**、靠**订单与库存对账**事后发现。这说明他已经能把「降级的代价落在谁身上」算清楚，只是没有把它命名为「危险回退」。

## Implications

- 第 5 课（可观测性与容量）正好承接本课遗留的两根线：**「对账才发现」= 事后发现，需要指标/对账任务**；**「失败要诚实」= 错误码与日志语义**。可在开头用 3 分钟把「未知就说未知」与错误分类（可重试/不可重试/需人工）合并讲。
- 下一次需要他**独立写一条 ADR**（不提供样例），专门验证三节是否还串位；若仍串位，再单独加一节辨析，而不是继续给样例——连续给样例会让「格式意识」变成「格式抄写」。
