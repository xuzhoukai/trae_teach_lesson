# 起点：已具备度量词汇，但场景表述缺少刺激源/制品/响应，且把可用性误当作错误率

用户在首次练习中独立写出三条带数字的质量属性场景，说明他已经掌握 P99、QPS、在线人数、人天这类度量词汇，并理解「质量要求必须有数字」这一要点——后续课程无需再从「什么是 NFR」讲起。

证据与关键缺口（来自 2026-09-29 第 1 课练习的原始输出）：

- 三条场景都缺少**刺激源**、**制品**、**响应**三要素，只有「环境 + 度量」，说明他的思考起点是「负载指标」而非「谁在什么状态下对谁做了什么」。
- **可用性被写成「正常流量下错误率 < 0.1%」**——场景里没有故障刺激，等于把性能场景换了个度量。这是本次最需要修正的误解：可用性场景的刺激必须是崩溃/超时/依赖不可用，度量是恢复时间与可用时间比例。
- 可修改性那条（新支付渠道接入 ≤ 6 人天）是三条中最接近合格的：刺激与度量都对，缺环境与「不影响既有渠道」的约束，且未区分人天与日历天。

第二次证据（同一会话，判断题：「订单支付成功后 5 秒内必须完成通知推送，允许最终一致」的刺激与属性）：他把**刺激源**填成「用户」、**响应**填成「5 秒内响应成功」、**响应度量**填成「最终一致性」，属性判为性能。

- 关键模式：**填不出某一格时会硬填**（为了凑「刺激源」而编出「用户」）。需要反复灌输「六要素是检查表，不是填空题；填不出来代表需求没想清楚，应去提问」。
- 尚未区分「约束/策略」（最终一致）与「度量」（≤ 5 秒、送达率）。
- 对**内部事件作为刺激**（支付完成这类状态变化事件）缺乏心理模型，只熟悉「用户请求」与「流量上涨」两类刺激。
- 他把两个质量属性（延迟 + 一致性挪移）写进一条场景——「一条场景一个属性」的规则需要再次强化。

Implications：下一课可以直接进入「从质量属性到拆分决策」，但需在开头用 5 分钟强化「故障刺激 → 响应 → 可用性度量」的句式，并引入 RTO/RPO、可用时间比例等术语。可用性/可靠性的区别、以及「约束 vs 度量」的区别各需要一次专门的辨析练习。
